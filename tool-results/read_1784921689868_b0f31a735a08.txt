     1→/**
     2→ * PaySwap Kernel — Canonical Type System (Global Liquidity OS)
     3→ * -----------------------------------------------------------------------------
     4→ * The kernel does NOT process payments. It manages GLOBAL LIQUIDITY.
     5→ * A payment is merely one possible liquidity movement.
     6→ *
     7→ * Every operation is represented as a desired liquidity state transition.
     8→ * The kernel answers one question:
     9→ *   "How can liquidity move from A to B with lowest cost, highest safety,
    10→ *    and highest reliability?"
    11→ *
    12→ * Canonical Financial Objects (Kubernetes Pods / AWS EC2 equivalents):
    13→ *   Country, Currency, Corridor, Reserve, LiquidityProvider, FinancialOperator,
    14→ *   Treasury, TwinToken, Wallet, Merchant, Customer, Ledger, Event, Workflow,
    15→ *   Route, Policy, AIRecommendation, LiquidityExecutionPlan, SettlementPlan.
    16→ *
    17→ * Single source of truth for kernel engines, API routes, and the Digital Twin UI.
    18→ */
    19→
