   232→- Key decisions:
   233→  · Connectors hold NO protocol refs — they only return Evidence. The "connector failure never mutates protocol state" invariant is enforced by construction, not by discipline.
   234→  · Idempotency cache only stores SUCCESS responses — a failed request can be retried by the caller with the same key (e.g. transient NETWORK).
   235→  · Cache hits are still audited and recorded in metrics (they ARE requests) but not in health (no upstream call means no health signal).
   236→  · Rate-limited requests ARE recorded in health (consecutiveFailures increments) because the local rate limiter denying is a real signal — but doQuery is NEVER called.
   237→  · Timeout enforcement lives in the BASE class (Promise.race with setTimeout), not the subclass. Subclass doQuery can also return TIMEOUT errors directly (e.g. for simulated slow responses) — both paths feed into the retry layer.
   238→  · Signed evidence uses HMAC-SHA256 over a canonical string (evidenceId|issuedAt|JSON(payload)). The signature replaces the kernel's placeholder evidenceHash AND is duplicated in payload.signature for visibility. verifyEvidence() uses timingSafeEqual to defend against timing attacks.
   239→  · Secrets are NEVER inlined in ConnectorConfig — only vault refs. The registry resolves them at boot and injects via setApiKey()/setSecret(). In production this is a Vault/AWS Secrets Manager lookup.
   240→  · Simulated response shapes mirror REAL API contracts (PSD2 balances, Daraja ConversationID, JSON-RPC hex wei, Horizon hal+json) so swapping the simulation for a real `fetch(endpoint, { headers })` is a 1:1 substitution.
   241→  · deterministicHash (FNV-1a) is shared across connectors so simulated balances/transaction IDs are stable across calls within a run.
   242→  · The retry layer's `executeWithRetry` wraps subclass doQuery in try/catch — if doQuery throws (it shouldn't), the throw is converted to an UNKNOWN non-retryable error and the connector returns a structured response (never propagates the throw).
