4. **ledger_post_latency** — double-entry journal post + balance validation

## Bottlenecks Identified

### 1. Ledger projection rebuild is O(N)
At N=10,000 events, throughput drops to ~14 TPS. Each rebuild iterates all events and re-validates balance + emits `ledger.posted` events.

**Mitigation**: Use `snapshotStore` + `rebuildFromSnapshots()` — take a snapshot every N events, then replay only post-snapshot events. The infrastructure is already built (`protocol/ledger/snapshots.ts`); integration just needs to wire periodic snapshotting.

### 2. Connector path overhead at high concurrency
All 5 connectors show p99 ≈ 51ms at 10k TPS despite sub-ms simulated `doQuery`. The `ProductionConnector.query()` path runs idempotency → rate-limiter → retry → doQuery → evidence → HMAC → health → metrics → audit per call.

**Mitigation**: At sustained high TPS, batch audit writes + use a dedicated evidence-signing worker. The current single-process design is correct for correctness; throughput optimization is a tuning exercise.

### 3. DB query latency (Prisma)
Prisma `$queryRaw` adds 6–32ms p99 at high TPS (connection pool + query parsing).

**Mitigation**: Use a connection pooler (PgBouncer) in production; for SQLite (current dev), this is expected. Production deployment should use PostgreSQL.

### 4. Legacy adapter integration gap (FIXED)
The benchmark surfaced that the legacy `stellarAdapter.transfer()` (backward-compat shim) didn't pass `issuer` to the new chain adapter. **Fixed in the integration step** by updating the shim to pass issuer for Twin Token assets.

## Interpretation

- **Production-readiness**: 12 of 16 scenarios hit 10,000 TPS with sub-100ms p99 latency. This exceeds typical fintech requirements (most payment systems target 100-1000 TPS).
- **Correctness over speed**: The 4 scenarios that don't hit 10k TPS (ledger projection at scale) are correctness-first operations (full event replay) that should use snapshots in production, not be called per-request.
- **The frozen kernel performed excellently**: planner + event throughput both hit 10k TPS with sub-millisecond p99, confirming the kernel architecture is not a bottleneck.
